	-> viel Ram verbrauch

Performance:
	Algorithmische Komplezität der Algorithmen
	-> normale Matrix Multiplikation -> O(n^3) (worst, average, best-case) (unter annahme konstante multiplikationsgeschwindigkeit, scheint auf x86 zu stimmen)
	-> gustafson -> worst-case auch O(N^3), aber mit höheren konstanten Faktor
	   	     -> best-case O(1) (ließt no_values -> 0 -> fertig)
		     -> average hängt von sparse-heit ab -> nachschauen, wie es sich verhält
		     --> O(flops + nnz + n), also optimal wenn flops > max(nnz, n)
		     ---> solange mehr notwenige muls also values oder columns ist es algorithmisch optimal
		     ---> https://people.eecs.berkeley.edu/~aydin/spgemm_sisc12.pdf
		     -> konstante Faktor ist aber unterschiedlich!
